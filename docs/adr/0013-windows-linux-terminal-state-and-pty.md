# ADR 0013: Windows and Linux terminal state, PTY, and managed renderer boundary

- Status: Superseded by [ADR 0040](0040-cross-platform-libghostty-vt-terminal.md)
- Date: 2026-07-22

## Context

The pinned libghostty embedding surface currently provides an AppKit renderer and PTY only. Pretending that its `NSView` contract works on Windows or Linux would leak a macOS implementation detail into application operations and leave those platforms without a correct terminal. Asura also needs a canonical, headless terminal state for screen reads, exact key and mouse input, alternate-screen detection, and future agent automation; a plain redirected process or a text-only control cannot satisfy those requirements.

The desktop presentation must remain replaceable. `Asura.App` is allowed to understand Asura screen cells and input requests, but it must not reference a terminal emulator or PTY package directly.

## Decision

macOS continues to use the pinned libghostty shim and native `NSView` renderer. Windows and Linux use two version-pinned MIT-licensed libraries inside `Asura.Terminal`:

- XTerm.NET 1.0.15 parses VT100/xterm output and owns canonical cells, cursor, normal/alternate buffers, modes, scrollback, Unicode widths, generated key sequences, mouse protocols, bracketed paste state, title, and working-directory metadata.
- Porta.Pty 1.0.7 owns process and PTY lifecycle. It uses ConPTY and Windows job objects on Windows, and a bundled native `forkpty`/`execvp` shim on supported Linux architectures. Launch arguments and environment remain structured until the adapter invokes the library.

`PortableTerminalSessionFactory` implements the same `ITerminalSessionFactory` used by libghostty. The session starts a bounded asynchronous PTY read/write pipeline, incrementally decodes UTF-8 across read boundaries, feeds XTerm.NET under one state lock, and exposes only application-owned DTOs and capabilities. Terminal-generated protocol replies share the bounded writer path; inability to enqueue a reply is a visible session failure rather than silent data loss.

`TerminalScreenSnapshot` carries bounded plain text plus optional structured visible rows. Each cell contains text, display width, default/indexed/RGB colors, style flags, selection state, and optional OSC 8 hyperlink metadata. The snapshot also reports cursor/viewport coordinates and visibility, scrollback distance above/below the viewport, alternate-screen, bracketed-paste and mouse-mode state, window title, working directory, bounded visible OSC 133 command boundaries, truncation, and a content revision. No XTerm.NET type crosses the Terminal project boundary.

Exact key, mouse, scrollback, clear-scrollback, full-buffer Find, selection, selection-read, and paste requests are application operations guarded by the existing input lease. XTerm.NET generates state-sensitive sequences for the portable backend and owns its local viewport/selection state. Clear Scrollback erases viewport and saved content plus retained terminal metadata without sending `Ctrl+L` or any other PTY input, and advances a logical history floor so cleared blank rows cannot be revisited. Find searches the bounded active normal or alternate buffer, preserves wrapped-line and wide/combining-cell coordinates, wraps next/previous selection, and reports match count, selected index, and scan truncation through engine-neutral DTOs. On macOS, versioned shim entrypoints dispatch keys, mouse, and paste through libghostty's live surface state; mouse requests are rejected unless the terminal has enabled capture, while native scrollback, selection, and Find remain renderer-owned. A minimal reviewed patch to the pinned libghostty commit exports locked canonical cursor, viewport, alternate-screen, mouse, bracketed-paste, working-directory, and screen-text state to the shim. Unsafe paste is evaluated at the engine boundary against the durable terminal profile. `ProtectUnsafeIncludingBracketed` requires explicit confirmation even when bracketed paste is active; confirmed bracketed input uses the engine's paste path. The patched native artifact and shim smoke completed three consecutive clean runs before this decision was updated.

The Avalonia managed renderer consumes structured snapshots and sends typed Application requests. It never references XTerm.NET or Porta.Pty. A platform-neutral presentation host selects the native child on macOS and the managed child on Windows/Linux; the desktop composition root independently makes the matching engine selection. Cell geometry uses Avalonia's shaped advance and line metrics for the configured monospace face, and viewport updates carry the resulting explicit rows and columns so drawing, mouse coordinates, canonical state, and PTY size share one grid. A pre-arrange attachment starts at a safe 80×24 grid instead of the former minimum 2×1 size. Resize work is serialized and stale generations cannot commit after a newer session replaces them. Unsupported hosts fail with an explicit capability diagnostic.

The managed presentation polls screen snapshots at a bounded 20 Hz with one screen read in flight, invalidates only for a changed content revision/cursor/mode, and debounces resize bursts. It renders default, indexed, and RGB colors; bold, dim, italic, underline, blink, inverse, invisible, strike, and overline styles; wide and combining cells; selection colors; OSC 8 links; and the configured cursor. Its keyboard-operated Find overlay accepts text, Backspace, Enter/Shift+Enter/F3 navigation, and Escape, paints bounded query/status text, and publishes the same status through a polite automation live region. The surface suppresses input until initialization has fully attached the renderer and acquired its lease, then replays a pending focus request. A failed initialization detaches its locally held attachment at every setup stage. Avalonia's text-input-method client reports a bounds-clamped composition-caret rectangle, updates it during preedit/layout changes, and draws preedit text; committed text crosses the same leased `terminal.write` operation as ordinary text. Special keys and modifiers use typed operations. Wheel and Shift+PageUp/PageDown move local primary-buffer scrollback when mouse tracking is off; mouse-tracked wheel events remain remote, alternate-screen scrollback is not invented, and typed text/key/paste returns to the live viewport. Left-drag selection is local when mouse tracking is off, Shift forces local selection while tracking is active, selected wrapped/wide text is copied without emitting mouse input, and Ctrl+Shift+C/V obey clipboard write/read denial. `Ask` is satisfied only by the explicit human gesture. XTerm.NET exposes no safe system-clipboard broker, so process-originated OSC 52 reads return empty and writes are discarded for every profile value rather than crossing layers unsafely.

OSC 8 activation accepts only absolute `http` and `https` URIs. `Disabled` rejects activation, `Open` invokes an injected/testable opener, and `ConfirmBeforeOpen` displays the exact pending URI in a modal before invoking it. Confirmation re-checks the live profile, so switching to `Disabled` closes the prompt without opening. Quick Terminal consumes Escape to cancel either link or paste confirmation before considering window dismissal. Clipboard paste is sent through `terminal.paste`; an unsafe-paste result becomes a separate modal in-terminal prompt that retains pending text through asynchronous failure, blocks repeated/unrelated input while sending, and only retries after explicit confirmation. Because XTerm.NET 1.0.15 does not retain per-cell OSC 8 data or expose OSC 133/clipboard broker hooks, the adapter uses one bounded streaming OSC parser at the engine boundary; oversized sequences are discarded, OSC 8 text is stamped onto canonical cells, and visible OSC 133 A/B/C/D markers remain typed and engine-neutral.

Porta.Pty does not expose a portable foreground-process-group query. While a portable PTY process is live, a graceful user close therefore conservatively returns `ConfirmationRequired`; a confirmed close uses the force path and is reported distinctly. Once the process exits, cleanup is graceful. This favors data safety over silently terminating a possible foreground TUI. A future adapter may add platform job-control inspection without changing the application contract.

## Library evidence and support matrix

Both selected packages publish source, tests, NuGet provenance, and MIT licenses. XTerm.NET is UI-independent and targets .NET 6; Porta.Pty targets .NET Standard 2.0 and publishes Linux x64/arm64 and macOS x64/arm64 native shims while using system ConPTY APIs on supported Windows versions. Asura records both licenses in release inventory and pins exact package versions so a dependency update is deliberate and conformance-tested.

Deterministic managed conformance tests cover incremental UTF-8, wide/combining and wrapped selection, full-buffer Find/navigation/truncation, true local scrollback clearing, ANSI/256/RGB/selection color, cursor position and visibility, bounded local scrollback, alternate buffers, resize serialization, application-cursor keys, SGR mouse input, bracketed-paste confirmation and sanitization, clipboard allow/deny plus brokerless OSC 52, OSC 8 policy/activation, window title, bounded OSC 133 boundaries, input readiness, initialization cleanup, IME caret geometry, process exit, close/force behavior, and engine/presentation selection. The 25-test backend suite present at the container run, including a real Porta.Pty process, passes in a Linux amd64 .NET 10 SDK container; that run found and now guards Linux's PTY-end `EIO`/exit race. The current 53-test terminal suite also passes on the development host. These tests do not substitute for the required packaged Windows and Linux desktop matrix. Before M2 is marked complete, packaged jobs must run the interactive-TUI, IME, clipboard, mouse, resize, alternate-screen, sleep/wake, and native PTY lifecycle fixtures on named supported systems.

## Consequences

- Windows and Linux gain a real PTY and canonical terminal state without coupling durable definitions, session host, agents, or App view models to vendor types.
- The same structured screen and typed input operations serve human rendering and future governed agent tools.
- Managed rendering can be tested headlessly, while macOS retains the lower-latency Metal/AppKit surface.
- The managed surface implements leased local scrollback, mouse selection and Ctrl+Shift+C copy, selection colors, and policy-governed OSC 8 activation. Selection/copy preserves wide and wrapped cells; links are restricted to `http`/`https` and default to a revalidated confirmation prompt. OSC payload retention, snapshot capture, selected text, and command-boundary history are bounded.
- Screen capture is bounded to prevent an extreme viewport or malicious terminal from creating an unbounded application response.
- Live portable sessions currently use conservative close confirmation because foreground job ownership is not observable through Porta.Pty.
- Windows/Linux native acceptance remains a release gate; passing the deterministic tests on macOS alone is not evidence of platform completion.

## Alternatives rejected

- Redirected standard streams do not provide PTY modes, resize, interactive TUI behavior, or correct job control.
- A platform UI control that owns an undisclosed second terminal state would make agent screen reads diverge from what the user sees.
- Referencing XTerm.NET or Porta.Pty from `Asura.App` would violate the engine boundary and complicate future protocol clients.
- Shipping GNOME VTE alone would not cover Windows and would introduce a GTK-native composition path separate from the required common contract.
- Treating the current libghostty `NSView` embedding ABI as cross-platform would be false capability reporting.
